# 场景、数据采集与合成：定向原文证据笔记

检索日期：2026-09-10。本文是本轮增补研究的证据笔记，聚焦 terminal、软件工程、computer use、Web GUI 和 API 工作流。论文机制以所链接的版本为准；“仓库已收录”核对的是 `long-horizon-1/data/repository_catalog.csv` 保存的 Awesome 仓库快照，不能解释为已经检查每篇论文全文。

## 1. 首先区分需要生产的五类资产

“有一万条任务”不等于“有一万条可训练长程经验”。建议将数据对象拆为：

1. **任务**：用户目标、约束、完成条件、信息初始可见范围。
2. **环境**：初始文件/数据库/桌面状态、依赖版本、工具定义、可恢复快照。
3. **轨迹**：每步真实 observation、action、执行结果、时间和成本；GUI 包含截图坐标和分辨率，API 包含请求响应与状态变化。
4. **验证器**：检查目标达成以及不允许的副作用，并明确允许的多种正确解。
5. **训练标签**：终局结果、局部错误、恢复分支、偏好对、必要时的过程奖励及其证据来源。

只生成“问题+理想回答”一般只能训练任务描述和回答方式；没有可执行环境与真实动作结果，就不能据此证明学到了长程交互能力。历史中的真实观测与教师补写的解释必须使用不同字段，避免把事后解释当作当时可见证据。

## 2. 场景与采集方案

下表中的采集建议是基于已读工作归纳的研究设计，不是各论文已经全部实现的功能。

| 场景 | 必须保留的数据 | 可行采集/合成路线 | 主要质量判据 |
|---|---|---|---|
| Terminal：依赖修复、系统管理、数据处理、构建与部署 | 镜像/版本、文件树和初态、命令、stdout/stderr、退出码、最终产物及服务状态 | 真实终端记录重建；从健康环境注入故障再生成修复任务；从技能说明共同生成任务和环境 | 新容器可复现、完成状态通过测试、原状态不冒充成功、避免破坏无关文件和绕过测试 |
| SWE：issue 修复、跨文件变更、测试维护 | issue、base commit、代码与依赖、补丁、测试、交互轨迹 | 挖掘 PR/issue 与修复提交；恢复修复前版本；人工或自动封装环境；教师真实执行采样 | fail-to-pass、pass-to-pass、隐藏回归、仓库/时间隔离；原作者补丁不应暴露给执行策略 |
| Desktop computer use：办公软件、跨应用操作 | VM 初态、截图/可访问树、屏幕尺寸、点击键盘拖动、保存的文档、应用状态 | 人类屏幕操作采集；教师在虚拟机执行；连续可解小任务合成为整体任务 | 动作与截图严格对齐；保存后的文档/文件内容检查优先于屏幕外观；跨分辨率和应用版本复现 |
| Web GUI：检索、表单、购物、后台操作 | 浏览器/站点版本、登录态、截图/DOM、动作、持久状态 | 可控站点上的人机轨迹；FSM 生成站点再搜索并回放；真实站点探索 | 页面交互可执行、服务器/应用状态达标、目标语义与状态机一致、真实站点迁移 |
| Tool/API：跨应用个人助理、企业流程 | API schema 与版本、响应、错误、分页、权限、跨工具数据库变化 | 基于真实 schema 实现可重置 simulator；经合法 API 程序化填充数据库；任务模板+反事实初态 | schema 正确仅是最低要求；必须检查最终数据库及允许/禁止变化，支持不同合法调用路径 |
| 混合任务：资料检索→数据处理→图表/文档→提交 | 上述多个环境的共享状态、依赖关系、产物版本和交接记录 | 在共同用户目标下组合跨接口任务；显式传递证据/文件并插入要求变更 | 端到端产物正确，前一阶段变化能够影响后续判断；长轨迹不能只是独立小任务拼接 |

terminal/computer use 是**交互界面**，writing/SWE/research 是**任务语义**，两者不是互斥类别。同一论文写作任务可能同时用浏览器、终端、编辑器；因此分类最好至少有 `domain × interface × environment × horizon` 四轴。

## 3. 七个代表工作的直接证据

### 3.1 CLI-Gym：健康环境反向构造失败状态

- **仓库定位**：R0306，README 第 532 行，Data and Environment Synthesis。
- **原始来源**：[论文 v1](https://arxiv.org/html/2602.10999v1)、[官方代码](https://github.com/LiberCoders/CLI-Gym)。读取论文 §3、附录 A、B.1-B.3，并读官方 README。
- **实际做法**：先取得能运行测试的健康仓库环境；根据测试生成干预方向，让 agent 改坏环境，并把故障状态总结成可重建的 Dockerfile；以失败测试和环境异常生成修复说明。29 个仓库最终产生 1,655 个任务。
- **轨迹与训练**：教师执行得到 417 条通过轨迹，剔除过短和利用历史遗留信息取巧的轨迹，保留 291 条做 SFT。附录 B.1 明确过滤 cached Git 信息、Conda 日志等非预期捷径。
- **边界（本笔记推断）**：覆盖程度依赖起始仓库、干预方向及测试。用 `<20 步` 剔除容易任务，是采样启发式，不能证明依赖链更长或能力更强。成功修复与故障真实频率、可维护性仍需独立测量。

### 3.2 Terminal-World：以 skills 同时约束任务、环境和教师

- **仓库定位**：R0339，README 第 565 行，Data and Environment Synthesis。
- **原始来源**：[论文 v1](https://arxiv.org/html/2605.20876v1)。读取 §3、附录 C.4-C.6。
- **实际做法**：筛选真实技能，以 persona 生成任务、环境蓝图、验收要求、执行指南，再建立文件、setup 与 pytest；生成-验证-修复后采集教师轨迹。指南在 SFT 输入中删除。共 5,723 个环境，单技能之外包含团队和技能图组合。
- **质量证据**：任务用五维 judge 筛选；验证器要求可运行且初态不通过。附录 C.6 已报告四个 judge 在 500 样本上的一致性，并有 200 样本、三人人评对照。
- **边界（本笔记推断）**：不能宣称该工作没有 judge 校准。更准确的问题是：这些一致性与抽样检查是否覆盖新故障族、训练后策略的取巧行为，以及跨环境迁移？“初态失败”也不等价于所有错误解均被拒绝。

### 3.3 SWE-Gym：真实 issue 必须补齐可执行环境

- **仓库定位**：R0288/R0527，分别位于数据合成和软件工程应用部分。
- **原始来源**：[论文 v1](https://arxiv.org/html/2412.21139v1)、[官方代码](https://github.com/SWE-Gym/SWE-Gym)。读取 §2.1、§3.1-3.2、§4；代码链接仅确认来源，未运行。
- **实际做法**：从真实 Python 仓库 PR/issue 提取问题、代码快照和补丁，按版本处理依赖，再以补丁前后测试变化验证；11 个仓库提供 2,438 个可执行任务。论文明确区分包含 issue 的 Raw 集与可执行环境集。
- **成本与训练**：环境构造报告约 200 人时、10K CPU core-hours；教师采集 491 条成功轨迹做过滤行为克隆；成功/失败标签也用于训练 outcome verifier 来排序候选解。
- **边界（本笔记推断）**：issue 爬取规模不代表可训练环境规模；环境工程是独立成本。测试覆盖与真实功能正确性不等价，Python 仓库分布与完整软件生命周期存在差别。

### 3.4 AgentSynth：先执行可解子任务，再总结整体目标

- **仓库定位**：R0304，README 第 530 行。
- **原始来源**：[论文 v1](https://arxiv.org/html/2506.14205v1)、[官方代码](https://github.com/sunblaze-ucb/AgentSynth)。读取 §3、§4.1-4.2 和官方 README。
- **实际做法**：在 OSWorld 虚拟桌面根据 persona 提议小任务，执行、看截图验证，再从当前状态提出后续任务；若只完成部分，则重写任务以匹配已做部分；最后合并子任务为长程指令。观察是截图，动作经 pyautogui 执行。
- **判准证据**：judge 提取要求和关键截图后判断；论文 100 例人审中 verifier accuracy 为 89%，现实可行性 87%，连贯性 91%。不能把此 judge 当精确真值。
- **边界（本笔记推断）**：部分完成后改写任务会产生“可完成目标偏好”，需要另留原始目标及失败原因；截图不一定暴露已保存文件或后台状态。论文也承认其难度主要依据 horizon/组合性，尚需与界面陌生程度分开。

### 3.5 AutoWebWorld：状态机搜索和真实前端回放

- **仓库定位**：R0305，README 第 531 行。
- **原始来源**：[论文 v1](https://arxiv.org/html/2602.14296v1)、[作者项目页](https://evanwu1125.github.io/AWW_homepage/)。读取 §3-5.1、附录 D.4；项目页链接由论文提供。
- **实际做法**：生成显式 FSM，编码状态、前置条件和变化；生成网站，通过 BFS 生成到达目标的路径，再用 Playwright 回放并过滤失败交互，之后生成自然语言 query。29 网站共 11,663 条轨迹。
- **训练口径**：去重取 1,215 条轨迹、12,585 交互步，再加 grounding 约 16K 样本。GRPO 奖励是动作类型、坐标框和格式匹配，并非原文已证明的完整在线长程终局 RL。
- **边界（本笔记推断）**：FSM 内正确不自动证明真实网站语义正确；同源规格会传播共同错误。真实评测仍用 LLM judge，限定 15 步并筛选访问稳定站点，不能据此推出任意长度及动态网站稳健性。

### 3.6 AppWorld：程序化状态质量与副作用检查

- **仓库定位**：R0762，README 第 1088 行，General-Purpose Agents。
- **原始来源**：[论文 v1](https://arxiv.org/html/2407.18901v1)、[官方代码和文档](https://github.com/StonyBrookNLP/appworld)。读取论文 §2-3、README 的任务世界、评估和数据分割说明。
- **实际做法**：人工工程化实现 9 个应用和 457 个 API；经 API 程序化生成互相一致的虚拟用户活动，少量文本辅助用 LLM。每场景同时编写 setup、solution、evaluation，改变初态构造任务和对照组。
- **质量证据**：评价数据库变化是否包含必须变化且仅有允许的额外变化，支持多种正确调用路径并检查副作用。750 任务中 train 105、dev 60，测试不可混作训练数据；公开文档支持在线求评价作为 RL 信号。
- **边界（本笔记推断）**：该工作已经解决固定 simulator 内的多解和副作用检查，不能当成空白。开放环境扩展、自动生成同质量语义合同、真实 API 变化和更长持续任务仍需额外证明。

### 3.7 补充：TerminalWorld，真实终端录像反向重建

- **收录状态**：在本地快照按标题、`TerminalWorld` 和 `2605.22535` 检索未命中。它是与上面的 skills **Terminal-World** 不同的论文，不能混用。
- **原始来源**：[论文 v1](https://arxiv.org/html/2605.22535v1)、[官方代码](https://github.com/EuniAI/TerminalWorld)、[作者主页](https://terminalworld.ai/)。读取论文 §3.1-3.4、§4.2 和作者主页。
- **实际做法**：80,870 条公开 asciinema 记录，经筛选、意图与参考命令提取、Docker 重建、执行测试，得到 1,530 个任务，另有 200 个人工核验任务。
- **判准证据**：测试必须通过三类实验：参考解全部通过，no-op 不通过，截断/消融解至少有测试失败；作者人工检查指令与测试约束一致。
- **边界（本笔记推断）**：真人记录仍受演示上传和可重建性筛选偏差影响；论文排除 TUI、Windows、不可访问资源。三类试验对训练期间新出现的策略漏洞没有完备保证。单纯“加入 partial tests”已有先例。

## 4. 关于“仓库没有解决什么”的谨慎结论

Awesome 是文献目录，不是一个统一完成度可测的系统。上述证据能支持“代表工作仍留下什么边界”，不能支持“整个研究领域从未有人做过”。在提出新论文前，应继续检索下列方向的最接近工作。

| 不宜宣称的空白 | 已有反例 | 更有依据的未充分解决问题 |
|---|---|---|
| 没有长程任务合成 | CLI-Gym、AgentSynth、Terminal-World | 真实目标下的依赖图覆盖、跨接口组合、对未见组合的训练迁移 |
| 没有 judge 校准/人审 | AgentSynth 人审；Terminal-World 多 judge 与人审 | 按任务长度、故障类型和策略版本分层校准；有限人工预算如何分配；何时拒绝评分 |
| 没有自动验收/副作用检查 | AutoWebWorld、AppWorld | 自动合成的验收规范本身如何独立验证；在新应用/新版本及动态环境中保持可信 |
| 没有错误解测试 | CLI-Gym 过滤捷径；补充 TerminalWorld 三类试验 | 对策略主动搜索的 reward hacking、语义错误与副作用持续建立难负例，并测真实收益 |
| 只要轨迹够长即可 | AgentSynth 已讨论难度混杂 | 控制动作长度时独立改变依赖深度、记忆间隔、分支、干扰和恢复难度，验证长度之外的能力 |
| 没有数据后训练 | SWE-Gym SFT/verifier；AutoWebWorld 动作级 GRPO | 同预算比较数据获取、验证、SFT、在线长程 RL 的收益；验证器偏差如何影响策略优化 |

建议优先研究的问题是：**合成任务、独立验收和训练策略之间的闭环可靠性**。有价值的实验应让验证器遇到未参与其生成的错误解和训练后策略，且在未见环境/技能组合上检验。只报告教师通过率、judge 均分、轨迹长度或训练集 reward，都不足以替代真实任务完成率。

## 5. 可以直接采用的数据质量检查设计

以下为研究建议，而非声称现有论文已经统一采用的标准。

- **环境可执行**：从干净快照初始化，参考轨迹至少多次重放；记录依赖、状态、时间和随机因素。
- **合同一致**：任务约束、环境能力、测试条件逐条对应；不要通过测试时才引入用户未声明的输出格式。
- **正确解包容性**：至少包含不同操作路径的可接受解；避免把参考动作 exact match 当作全部任务正确性。
- **错误解辨识度**：无动作、部分完成、错误对象、遗漏约束、错误保存、无关副作用、伪造产物、读取答案遗留文件等分开测；已有 partial-test 工作须作为基线。
- **长程属性有效**：保留依赖图和中间产物关系，报告动作数之外的关键依赖深度、信息保持间隔、应用切换、恢复次数。
- **judge 可校准**：在人审分层集上报告假阳性/假阴性、分歧及置信区间；只报告平均一致率会隐藏稀有但严重的错误。
- **迁移与泄漏控制**：按源仓库、技能祖先、任务模板、应用版本和时间划分，不能把同一任务的改写随机分到训练和测试。
- **训练价值**：在相同模型、训练 token、rollout 和评测预算下比较收益；失败轨迹保留原目标与原因，避免全部重标记为成功任务。

LLM-as-a-judge 的合适定位是补充语义检查、整理 rubric、筛选高风险样本、帮助定位错误。程序可验证的文件/数据库状态应优先用独立程序验证；程序验证暂时覆盖不了的开放语义，再用经人审校准的 judge。多模型投票能降低部分随机波动，但不能单靠一致性排除共同盲点。

## 6. 最接近前作追加核对：跨天事件、混合接口与参数训练

### 6.1 ClawMark 已覆盖跨天外部更新和科研助理场景

- **仓库定位**：R0679，README 第 983 行。
- **读取深度**：[原文 v2](https://arxiv.org/html/2604.23781v2) §3-5、附录 A，并读[官方 README](https://github.com/evolvent-ai/ClawMark)。不是仅看摘要。
- **已实现**：每任务 2–6 个模拟工作日；外部更新包含通知事件与静默变更，注入新文件、改写表格、知识库和日历。五个有状态服务承载共享工作流，包含 15 个 research assistant 和 8 个 journalist 任务。不能把“跨天外部事件”“办公材料变化”“跨服务对照”单独当新问题。
- **构造与质量**：人工任务优先设计、三种带来源标签的材料采集/合成、3–5 轮人机审查。审查已包含 checker-hacking、任务与检查器对应关系及两种参考模型轨迹的独立复核。
- **参数训练边界**：已读实验主要是统一 OpenClaw 下比较现有模型，未报告用该数据 SFT/RL 带来的收益；正文提及但未报告内部 tuned 变体，不足以声称完全没有相关训练。这里的“日”是模拟回合，不是实际运行数日。
- **版本提醒**：README 的天数/检查器范围与论文不同，应使用明确的论文 v2 口径；未执行任务复现。

### 6.2 OSWorld-MCP 已覆盖同一环境内 GUI/MCP 选择

- **仓库定位**：R0329，README 第 555 行。
- **读取深度**：[原文 v2](https://arxiv.org/html/2510.24563v2) §3-4 及附录工具清单，并读[官方代码 README](https://github.com/X-PLUG/OSWorld-MCP)。
- **已实现**：agent 每步可在 GUI 操作和 MCP 中选择，作用于同一桌面和应用；工具包括 Writer 文档、Calc 表格、Impress 演示和系统文件操作。工具由代码解生成与已有服务器汇集后经双人人审，最终 158 个；实验对比 GUI 与 GUI+MCP，使用 15/50 步限制。
- **边界**：该论文是工具构造和评测工作，已读方法/实验未报告参数训练，也没有 ClawMark 式跨天外部事件设计。“动态交互环境”不要解释成已经实现独立外生事件流。原文与后来修复 LibreOffice 工具后的 README 数字不同，不能混用。

### 6.3 ToolCUA 已覆盖 GUI/工具交织数据、SFT 与在线 RL

- **收录状态**：旧快照按 `ToolCUA` 检索未命中；线索来自 OSWorld-MCP 官方 README。
- **读取深度**：[原文 v1](https://arxiv.org/html/2605.12481v1) §2.1-2.4、§3.1 与实验表 2；同时读[官方项目页](https://x-plug.github.io/ToolCUA/)和[官方代码 README](https://github.com/X-PLUG/ToolCUA)。方法判断基于全文，不仅是摘要。
- **已实现**：从真实 GUI 轨迹抽象合成工具，并把预测工具效果对齐到原轨迹后续截图；再混合 GUI 与工具步骤。先 warmup SFT，再对切换点单步 GRPO，最后在真实 GUI-Tool 环境中做多轮 GRPO；终局成功之外，工具使用与长度奖励仅在成功轨迹激活。
- **实验边界**：§3.1 明确在线训练使用 OSWorld 任务并排除 multi_apps，主测为 OSWorld-MCP；因此其总体成绩不能统称未见任务泛化。论文另外报告留出的 multi_apps 和 Windows 环境迁移。没有在已读方法中看到跨天材料更新或科研稿件版本一致性训练。
- **发布边界**：官方 README 仍把数据流水线与训练基础设施列为待发布项；“论文有训练实验”不等于已获得完整可复现训练代码。

### 6.4 对研究空白的具体收窄

| 原方向 | 必须承认的已有覆盖 | 更谨慎的剩余问题 |

| G1 跨接口共享状态 | OSWorld-MCP 已有 GUI/MCP 共同环境；ToolCUA 已有交织合成及参数训练 | **跨天外部更新之后**，接口配对数据中的工件、证据和记忆版本是否一致；能否在隔离任务与事件族上证明训练迁移 |
