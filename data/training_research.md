# 训练路线与仓库覆盖边界：研究笔记

核查日期：2026-09-10。仓库口径：`RUC-NLPIR/Awesome-Long-Horizon-Agents`，快照 `084cafe83e3d10814ae0b63329bd10aa5945fd97`；条目编号来自 `long-horizon-1/data/repository_catalog.csv`。本笔记回答“数据有了之后如何训练”，区分论文已验证结果和建议方案；不是训练实验结果。

## 1. 先确定拥有的是哪一种“数据”

长程 Agent 的训练样本至少涉及：任务目标、可见历史、动作、环境返回、终态或阶段验证。仅有最终报告、代码补丁或完成截图，可以训练产物生成；若要训练工具选择、执行、恢复和记忆更新，还需要对应过程与状态。

| 手上已有的资产 | 可以直接做什么 | 还缺什么 |
| --- | --- | --- |
| 静态成功轨迹，含真实观察与动作 | SFT、离线轨迹蒸馏 | 学生犯错后的状态覆盖 |
| 同任务或同状态的好坏候选，以及可信比较标签 | DPO 或其他偏好优化 | 比较依据、标签不确定性、长度与任务难度控制 |
| 初始状态、任务生成器、可重置执行器、终态验证器 | 在线 Agentic RL | rollout 预算、稳定训练、信用分配 |
| 可交互环境，以及能在学生实际状态下提供动作/分布的教师 | DAgger 类纠错、OPD | 教师在异常状态下的可靠性、蒸馏与重采样成本 |
| 用户实际反馈与持久记忆日志 | 离线纠错与持续学习研究 | 时间切分、重放条件、用户偏好变化与错误归因 |

综述 §5.4–5.6 已分别覆盖轨迹 SFT、Agentic RL 与 OPD。AgentGym-RL 已提供 SFT、DPO、PPO、GRPO 等训练入口和交互调度；所以“缺一个支持长程训练的框架”不能作为当前创新点。[AgentGym-RL 官方仓库](https://github.com/WooooDyy/AgentGym-RL)

“有轨迹 JSON”与“有 RL 环境”不同。在线 RL 的下一条观察必须由当前动作实际执行得到。离线日志中的下一条观察不能无条件接在学生新动作后面；那会把不真实的状态转移当作训练证据。离线 RL 可以研究日志利用，但同样需要明确覆盖度、行为策略与离线分布约束，不能把普通 SFT 改名为在线 RL。

## 2. 推荐训练顺序，以及每一步的准确含义

以下是面向研究原型的建议流程，不是要求所有项目必须完成所有阶段。

### 2.1 阶段 A：固定接口与样本边界

先选择部署时的工具接口、观察格式、上下文预算、记忆工具和终止方式，再做数据转换。视觉 GUI 任务需要能处理截图的视觉模型及对应动作表示；纯文本模型的训练不自动提供像素 grounding 能力。

每条轨迹记录 `task_id/source_family/environment_version/initial_snapshot_id/policy_version/teacher_version/verifier_version`；每步记录 `observation/action/tool_result/state_hash/validity/reward_components`。这些是本笔记建议的扩展字段，不声称 ADP 原生全部规定。

ADP 的价值是把不同数据源转换为统一动作与观察，再转换到目标 harness。它已经处理格式异构，但其原文的质量检查主要涉及工具调用格式、对话结束和思考字段覆盖。格式合法不证明工具结果真实，也不证明任务成功。[ADP §3.2–3.3](https://arxiv.org/html/2510.24702v2)

### 2.2 阶段 B：轨迹 SFT 冷启动

目标是先学会合法工具调用、读取反馈、执行修复、更新记忆、正确结束。建议混合完整成功轨迹与经验证的恢复轨迹，按场景、任务难度、依赖深度和失败类型抽样；不能让大量一步式数据吞没少量长程数据。

推荐的动作监督形式为：

\[
\mathcal L_{SFT}=-\sum_{\tau,t,j}w_{\tau,t}m_{\tau,t,j}\log\pi_\theta(a_{t,j}\mid h_t,a_{t,<j}).
\]

`m=1` 对应选择监督的 assistant 动作/答复 token；用户消息、工具返回、环境 observation、截图输入、padding 的动作预测 loss 为零，但它们仍是可被关注的输入。若另有观察预测或世界模型辅助任务，应单列损失及实验，不能混成 Agent 动作监督。教师纠错应在学生真实历史上生成；不能把失败动作之前与另一条成功轨迹之后的观察生硬拼接。

建议按完整动作或完整阶段切块；超过上下文时保留产生动作所需的状态摘要与证据来源。不要随机截取长对话片段后删掉关键前置条件，也不要把未来测试结果或最终答案放入早期动作可见上下文。训练“失败后恢复”时可将已发生的错误动作留作输入，只对经验证的恢复动作施加正向模仿损失。

AgentGym-RL 的 `RolloutHandler` 已明确负责多轮 action/observation 的 attention mask、loss mask 与位置等处理。训练实现应检查所选接口实际产出的 mask，而不能假设使用某框架就已正确。[AgentGym-RL：Extending Verl](https://github.com/WooooDyy/AgentGym-RL)

### 2.3 阶段 C：偏好优化是可选支路

适合有多个合理产物、质量不能完全机械判定的 writing、规划、信息整理。数据形态是同一需求下的候选对，或同一有效状态下的不同动作/续写，配有明确比较理由。DPO 用偏好对直接更新策略，无需先显式拟合一个奖励模型；但它不会自动修复偏好标签错误。[DPO 原始论文](https://arxiv.org/abs/2305.18290)

建议优先构造有可解释差异的候选对，例如同一文稿“引用确实支持结论”与“引用存在但不支持结论”；同一任务“恢复后完成”与“在同样错误后直接宣称完成”。先用机械与证据检查剔除硬错误，再比较组织、表达和覆盖度。

完整轨迹偏好可以来自相同初始任务，后续状态允许因动作而分叉；但若声称某一步更好，就应尽可能从同一可见历史及同一有效环境状态比较，并控制后续随机性。对多轮轨迹计算策略概率时，累加 Agent 自己生成的动作 token 概率；环境观察不是策略生成的文字。后续工具输出可以作为条件输入，不能作为待模仿输出。

仅用最后一稿 DPO 可以改善文稿偏好，但无法据此声称已经学会可靠的检索、事实核查或跨轮恢复。那些能力需要把对应决策纳入训练与闭环评测。

### 2.4 阶段 D：可执行场景再做在线 Agentic RL

每次采样：从固定版本环境重置 → 当前策略逐步执行 → 收集真实反馈 → 终态验证 → 计算收益与优势 → 仅更新策略生成动作的概率。先把 SFT 模型作为稳定基线，再比较无 SFT 的直接 RL；AgentGym-RL 的研究说明直接 RL 可行，并不意味着所有新场景都应跳过冷启动。[AgentGym-RL 论文摘要](https://arxiv.org/abs/2509.08755)

奖励建议保存为向量而非仅保存一个总分：任务成功、硬约束满足、事实/状态正确、恢复情况、动作成本、时延。先检查硬约束，再优化质量和成本；机械合规或多调用工具不应独立获得很高奖励。下面只是可供消融的设计例子：

\[
R=\mathbf1[\text{hard constraints pass}]\,(R_{task}+\lambda_qR_{quality})-\lambda_c C-\lambda_v V.
\]

其中 `R_quality` 只有在验证器达到预先声明的校准要求后才进入训练；未达标时用于诊断或人审，不能把“Judge 感觉不错”当作真实性证明。系数、门槛和惩罚应通过预实验确定，本笔记不声称存在通用数值。

逐步增加任务依赖深度和允许交互长度，但不要通过大量无关动作人为制造“长程”。需要同时统计有效依赖深度、动作数、token、工具耗时。GRPO 等方法在同组全成功或全失败时可能缺少有效相对信号，应通过分层采样、课程或新任务提高有效比较比例；增加组大小也不能替代可靠的终态验证。

### 2.5 阶段 E：学生分布上的纠错或 OPD

学生自己运行后，请教师在它实际到达的状态上提供纠正动作或 token 分布，比仅重复学习教师的顺畅轨迹更贴近部署。能获得教师概率分布时可做分布蒸馏；仅能取得教师文本动作时，可做 DAgger 类重新标注或动作 SFT，但不应声称实现了精确全词表 KL 蒸馏。

OPD 也存在教师不适配学生异常状态的问题。TCOD 通过逐步扩展学生承担的轨迹深度缓解多轮不稳定；其验证主要是 ALFWorld、WebShop、ScienceWorld，不能直接外推为长文事实写作或桌面 GUI 已解决。[TCOD §4、§5](https://arxiv.org/html/2604.24005v1)

异步训练还应记录行为策略与教师标签版本，并衡量延迟样本失真。f-OPD 针对 rollout 与监督的时效问题加入可靠性加权、约束和刷新；论文也明确说明证据局限于有限模型及推理、工具、编码任务，其分析不是收敛保证。[f-OPD §4、Appendix D](https://arxiv.org/html/2605.17862v1)

## 3. 按场景分别给出的训练配方

| 场景 | 冷启动数据与模型 | 下一步训练 | 奖励与评价证据 | 必须留出的测试变化 |
| --- | --- | --- | --- | --- |
| Terminal / coding | 指令+代码仓库版本+真实命令输出+补丁；动作 SFT，覆盖检查、修改、测试、失败恢复 | 容器或 VM 在线 RL；学生失败状态上的教师修复；代码接口固定后再比较算法 | 隐藏测试、文件系统状态、构建与回归；保留失败解释，不能只用 exit code 或 Agent 自述 | 新仓库/项目谱系、新 issue 类型、依赖版本、工具故障、更长依赖链 |
| Computer use / GUI | 截图/必要视频+动作+时间戳+窗口信息；视觉 grounding 与完整流程 SFT | 可复位 VM/browser 中在线 RL；先单应用，再跨应用及中断恢复 | 后端状态、导出文件内容、应用内状态优先；视觉 Judge 作为补充 | 新应用或网站、新布局、分辨率、弹窗、跨应用交接 |
| Research / writing | 冻结来源包+逐项 claim-evidence 对齐+提纲/草稿/修订轨迹；保留检索及引用动作 | 先证据监督 SFT；同需求候选的偏好优化；待 Judge 校准后再小规模 RL | 引用存在与支持性、必要内容覆盖、数值复算、版本一致性；组织表达用经人类校准的 rubric | 新主题、新文档源、新证据包、冲突证据、跨章节与后续修订要求 |
| Web / enterprise workflow | 工具 schema+数据库快照+权限状态+交易前后状态；流程与异常分支 SFT | 在测试账户/离线服务副本中交互 RL，奖励最终目标与约束 | 数据库/工单/日历最终状态、避免重复修改和跨对象污染 | 新业务流程、接口版本、权限、部分执行与重试 |
| 跨会话记忆 | 多会话顺序+事实生效时间+记忆写/改/删+后续任务；训练状态维护动作 | 同一记忆状态分支重采样，联合优化最终任务与记忆质量 | 未来任务效用、冲突处理、过期事实淘汰、存储预算 | 新用户/新项目、时间跨度、偏好变化、记忆污染与压缩 |

这些是本文建议组合，不是某一篇论文已验证的统一配方。尤其 writing 的“写得好”与“证据足”必须分开监督；terminal 的机械验证优势也取决于测试覆盖，测试通过不等于规格完整。

## 4. 信用分配：不能把一次成功平均奖励给所有动作

1. **终态信用**：任务完成可确认，但不知道哪一步起决定作用。可作为第一版可靠基线，先确保奖励正确。
2. **阶段信用**：把可观察、必要的子目标成功作为辅助反馈。避免把“出现计划”“调用验证工具”等表面行为等同进展。
3. **同状态反事实比较**：从相同有效环境状态重新执行不同动作，比较后续收益。需要真实快照或可靠重放，不能仅凭相似截图就认定状态相同。
4. **统计可靠性**：相同动作少量采样偶然成功时，应收缩估计或降低权重；无有效对照的状态可以退回终态信用。

仓库已有两项直接相关工作。Memory-R2 以同一记忆状态的局部 rerollout 配合全局目标，回应不同记忆历史造成的不公平比较；其奖励涉及下游 QA F1 和记忆预算，不能据此说已验证跨应用真实工作流。[Memory-R2 §3.3](https://arxiv.org/html/2605.21768v1)

ECPO 已研究重复 anchor 状态、动作归一化、低样本收缩和方差门控，主要在 ALFWorld/WebShop 评估。它说明“更密的信用”还需统计证据。开放文本写作的等价动作定义、GUI 隐含状态、外部系统不可逆副作用下怎样构造有效 anchor，仍需要额外机制与验证。[ECPO §4、§5](https://arxiv.org/html/2606.05885v1)

注意：这里没有把“所有完整轨迹必须具有相同中间状态”作为 GRPO 的普遍要求。相同初始任务允许后续分叉；问题是在已经不同的中间状态上，直接把收益差解释成某个局部动作的因果优劣。

## 5. 评测切分必须先于合成与训练

下面是建议的实验设计，旨在防止合成模板和来源泄漏造成假提升：

- **按来源/项目/任务家族切分**：同一个 GitHub 项目的同源代码、同一网站模板、同一主题来源包及其所有改写放在同一组。不能将同一 seed 的不同语言改写随机分到训练/测试。
- **单独隔离校准集**：奖励权重、Judge 提示词、阈值与人类校准均在开发/校准集确定；最终测试不参与生成器、验证器和模型选择。
- **分别报告长度外推与场景外推**：在相同接口下测试更长依赖链；在相近深度下测试新应用或主题。这样才能知道学到的是长程能力还是领域记忆。
- **增加错误恢复测试**：工具超时、测试失败、页面更新、矛盾来源、早期记忆删除；报告完成率和恢复率，而不只报告正常路径均值。
- **固定比较预算**：同起点模型、harness、可见信息、有效训练 token、环境交互和教师调用成本。比较多次采样上限时，另报 pass@1 和固定成本成功率。
- **检查长期约束与校准**：随依赖深度的成功率曲线、假成功率、关键约束违反率、每成功任务成本；对概率型 Judge 报告分场景校准与置信区间，对偏好 Judge 报告排序一致性、位置/长度干扰下稳定性。

最小有信息量的消融为：基础模型 → SFT → SFT+学生纠错 → SFT+RL 或 OPD；再单独比较“只有终态奖励 / 加阶段奖励”“仅格式过滤 / 加执行与证据验证”“自然比例混合 / 按场景与难度平衡”。不需要在资源有限时机械跑全排列，应围绕提出的研究假设控制其余变量。

## 6. 仓库里已有解法之后，仍可研究的具体缺口

“仓库未解决”在这里指已核查作品的证据未闭合，不代表整个领域没人做过，也不是仅凭目录没有相同关键词断言新颖性。

| 可研究问题 | 仓库里已经做到什么 | 仍需完成的证据/机制 | 可证伪实验 |
| --- | --- | --- | --- |
| 跨 terminal、GUI、writing 的可执行经验协议 | ADP 统一数据并对接多个 harness；AgentGym-RL 提供多轮交互框架 | 状态快照、产物版本、来源证据、视觉轨迹、长期副作用与统一验证的组合 | 相同预算下，看新接口、新来源和跨场景任务能否迁移；检查转换后行为可重放率 |
| 质量过滤是否真的提升长程策略 | ADP 处理格式；不同论文提供执行、rubric 或过程反馈 | 数据过滤分数与训练后真实成功率的关系，尤其低质合成轨迹如何污染后期步骤 | 同 token、同任务覆盖控制，比较过滤策略的下游提升与失败类型，不只比较 Judge 均分 |
| 多场景混训的冲突与共享能力 | ADP 已做数据整合和跨数据源训练 | 同一策略在命令、像素动作、引用写作间的共享与干扰；论文实际采用 harness 分组 | 专项模型、简单混合、结构化混合比较；报告各域退化与跨域工作流收益 |
| 无完全可执行标准的 writing 奖励 | 仓库已有 rubric reward、PRM、Judge 等方向 | 引用支持、事实冲突、全局一致性与读者偏好如何组合，并经人工真值验证 | 制造“更流畅但更不实”的对照，检验奖励能否抵抗优化后的投机 |
| 开放状态空间的局部信用 | Memory-R2、ECPO 已分别处理记忆分支与统计信用 | GUI 隐状态、真实工具副作用、文稿长依赖下可靠的同状态反事实 | 对照局部分支估计与受控真实干预；测归因准确率及任务提升 |
| 异步长程训练的反馈过期 | f-OPD 已处理策略/监督滞后 | 来源网页、工具版本、用户偏好、持久记忆改变造成的环境/事实过期 | 控制策略不变而仅改变环境或事实版本，测旧数据过滤和再验证是否有效 |

其中第一、第三项尤其应谨慎表述：ADP Appendix C.1 实际把 OpenHands/SWE-Agent 训练数据筛为 non-web，把 AgentLab 筛为 web。因此该论文不是单一策略已经同时完成 terminal+GUI+writing 混训的证据；其 §7 还把多模态、统一评测和更强验证列为未来方向。[ADP Appendix C.1、§7](https://arxiv.org/html/2510.24702v2)
